## Consolidated findings and repair requirements

**F01 — P1, durable handoff/outbox continuation.** `record_review_handoffs` commits state=recorded before publication/enqueue. Duplicate path returns no blocks/delivery, and watchdog excludes recorded. `recover_pm_outbox` confirms only publication; it does not run the remainder of `run_pm`. Persist plan and phases with each owed effect; recover published bytes first, then safely apply owed ask dispositions/local queue creation. Atomic unique delivery keys must reconcile an enqueue that landed before its phase update. Probe01 reproduces the lost recorded instruction. Require crash injection after record, uncertain POST/readback, before/after enqueue, before/after marking delivered, and startup. Never replay an uncertain external write.

**F02 — P1, one route arbiter and persistent prerequisite gate.** `run_pm` holds ordinary next=dev but explicit review rows still enqueue; the separate anti-idle thread later queues active work without knowing the HOLD. A route with both review_handoffs and next=dev creates two Dev rows. Review dispatch also bypasses `auto_pm_to_dev`, parent's auto_handoff and continuation depth control. Probes02/07/08 reproduce these interactions. Persist readiness/dependency/generation on the task and apply one atomic arbiter to every route. Explicitly independent work may proceed. One directive produces one delivery; uncertain invocation is not a license for a second turn.

**F03 — P1, request ledger and dependency lifecycle.** Only first REQUEST line is parsed; numbered multiline and plain PO instructions are not independently durable. A later unrelated comment with source ID + NOT DONE closes a request. HOLD closes it too and loses release-event follow-through. Probes03/05/06. Add a typed request envelope with stable IDs, owner, task/candidate, source, dependencies and states pending/held/dispatched/completed/superseded. Legacy parser must preserve all REQUEST lines and list items; ambiguous text stays unresolved for PM classification. Carry held work into each applicable turn and re-evaluate on its named release event. Validate each disposition against its ask/candidate and evidence rather than accepting any SHA/link. Generic prose, negation, quoted directives and unrelated HOLD never retire it.

**F04 — P1, trustworthy receipt versus action/closure.** `record_handoff_receipts` permits any external non-board body quoting an App Dev token, even before delivery, and makes a dispatched ask completed on token echo. Probe04. Require expected actor envelope, task/candidate, dispatch generation, owner delivery and explicit receipt semantics. Separate received, started, result returned, PM reviewed, accepted/closed. A token alone proves neither action nor review completion. Because actors share a GitHub account, actor identity cannot be established by login alone; validate the app's dispatch/receipt channel and role contract. Keep receipt timeout and action timeout distinct.

**F05 — P1, integrated packet read and recovery.** `_gh_raw` bypasses GH_BACKOFF_UNTIL (probe10), maps every CLI failure to FileNotFoundError, and `_try_fetch` hides failure categories. Manifest is fetched twice; endpoint has no durable request, retry budget, source failure record or fallback reviewer queue. Integrate the already-posted 6048815645 requirement: exact repo/commit/path/manifest, shared rate-limited reader, bounded supported fallback, hash equality, categorized failure, persisted age, authorized reviewer routing/receipt, direct findings to owner. An absent reviewer transport remains explicit OPEN capability blocker. Add per-packet/file/byte/time bounds; no substitute moving branch or credential workaround.

**F06 — P1, complete review and qualification coverage.** `github_watch_snapshot` watches one selected PR; `poll_refreshed_reviews` only records matching Codex hits for completed refresh journals, not separate Security state or pre-PR PM acceptance. Review reads use first100 without pagination-completeness guard in the watcher, failures become empty, edited comments with existing IDs do not generate events, and obsolete pending candidate journals keep polling without invalidation. Build a bounded affected-task registry, durable review IDs/head/base/role/results, freshness and stale-candidate termination. A completed review must flow through per-finding disposition and exact owner delivery. The existing qualifier remains the authority for CI qualification; never infer Security or acceptance from generic bot hits.

**F07 — P1, action authority, PM lease and singleton.** The executor checks same account and SHA mentions; even an explicit Do NOT execute Draft→Ready passes (probe15). There is no host-enforced cross-PM action lease; semantic dedup works only against shared journal. Binding port is not a state-dir singleton: a second different-port start can reclassify another live running claim as unconfirmed (probe14). Require affirmative kind/candidate-scoped authorization bound to immutable source, applicable executor and expiry/consumption; fail closed for contradiction/ambiguity. Claim a durable operation lease before mutation, checkpoint/read back other PM actions, and lock the board state/repository against duplicate active worker sets. Startup recovery requires evidence the prior holder is gone, not just a new process starting.

**F08 — P1, verified task checkout and safe bootstrap.** `enqueue` saves branch/path, leaves target_head blank; `resolve_dev_target` accepts a changed HEAD and dirty checkout (probe13). Validation accepts any Git root with matching branch, without verifying SpeakSharp repository/common-dir, task-owned changes or expected tree. Add task-specific repository/base/head/tree/lease generation and explicit allowed owned dirty state. Freeze before queue commit and revalidate before invoking. A bootstrap task must run on an available verified checkout, preserve prior bytes, then transition same lease only on actual created-tuple evidence. On preflight block, recover PM once; no blind Dev retry. Do not require a universally clean tree on legitimate owned continuation: require ownership/evidence for the dirty state.

**F09 — P1, interrupted action recovery survives transient reads.** A transient read HOLD during resume sets held; the next execute deletes that row and starts from scratch, refusing the Draft it previously created. Probe11 strands it after one Draft write. Preserve phase for transient failures, retry only safe reads after shared backoff, and resume the prior owned lifecycle. Read changed/closed/main/scope/lease state before remaining writes. mark_ready lacks final readback; open-Draft/CI uncertain actions have no typed readback resolver. Give each supported operation a readback/uncertainty resolution state rather than quarantining indefinitely or replaying writes. Code/Security remain pending after lifecycle success.

**F10 — P1, transport/schema parity at the host boundary.** `_run_pm_command` drops review_handoffs, ask_dispositions and dev_depends_on_actions (probe12). Host parser does not enforce full schema on command/API routes; booleans and values can be coerced. Preserve all route fields and validate the same schema before board changes or effects for every mode. Malformed route stays explicit, bounded recovery without writer or accidental action. Nulls retain the documented meaning. Do not make a transport choice silently change coordination semantics.

**F11 — P1, bounded reads and durable budgets everywhere.** Initial fetch_watch_comments uses --paginate with no since (probe09); publish_pm_reply's marker fallback also reads all history. First/restarted cursor needs an explicit bounded lookback and bootstrap reconciliation of older open work, not silently dropping it. Incremental edits need updated_at/body generation detection. Outbox recovery needs source/post timestamp window, durable reset/backoff and bounded pagination. Cursor moves only after durable event retention. Qualifier/planner/raw paths must obey shared budget, with an explicit adapter contract where subprocess internals cannot share it. Rate limits stop work until reset rather than becoming missing-file reports or retry loops.

**F12 — P1, invocation/error/stop semantics.** Dev process wait has no bound; invocation errors return without informing PM. In-flight failed_uncertain work can be retried through API without proving whether it wrote. Add bounded execution/watchdog with task checkpoint, cancellation/termination evidence, and named PM recovery on transport failure. Distinguish selected, launch attempted, actual process started, reply, publication, receipt and action. A stop/pause must cover every dispatch route. An uncertain result needs readback/reconciliation and a new authorized continuation, not the generic retry button.

**F13 — P1 acceptance gap, actual external delivery.** c4 explicitly lacks external App Dev/Browser PM wake. A token published to GitHub is not a delivered desktop/chat task. Add a supported configured adapter or route to an available authorized local reviewer/executor capable of the work; preserve role ownership. The adapter must expose queue, delivery, receipt and missing-permission/capability states. Do not introduce an unapproved MCP server, simulate a wake, send the PO to shuttle messages, or grant a substitute actor permission implicitly. If no supported transport exists, full five-actor autonomy remains HOLD with that exact missing capability.

**F14 — P2, truthful UI and stable scope.** Historical train wins over explicit current selection (probe16); separate train priority from explicit selection and affected-task observation. `renderLedger` ignores dashboard.handoff_blocker; escalation/error settings are not cleared by resolution. Repeated identical blocker patches reset blocker_since. CLI dashboard overrides task blocked state with available when process idle. Launcher still announces deadlock.4 while server/UI announce deadlock.5. Expose source-linked phase, owner, exact failure, next release event and receipt/start age; derive blockers from currently unresolved state, suppress duplicate directives and correct build identity. Retain four displayed PR cards unless separately changed; they must not cap monitored tasks.

**F15 — P1, local HTTP command boundary.** Loopback binding does not validate web request origin. `H.do_POST` parses JSON without Content-Type, Host/Origin or per-session control-token checks. The server would accept a foreign-origin simple text/plain POST wherever browser/network policy permits it; response-reading restrictions are not request authorization. Add narrowly scoped Host/Origin validation and session control authentication for mutating endpoints, with same-origin UI handling and non-browser adapter tokens. This is a source finding, not a performed browser exploit. Test rejected foreign-origin/text/plain dispatch/reset/retry and accepted same-origin authenticated controls; preserve safe read endpoints.

**F16 — P2, upgrade artifact continuity.** New-directory migrate_state copies DB/uploads only, not handoffs or attachment path mapping. A failed migration can leave target DB present, suppressing another import. Make migration staged/atomic with manifest, artifact continuity/rebased or stable paths, explicit source selection and preserved originals. Existing same-folder upgrades already preserve local packets; retain that behavior. Document rollback limits and verify actual build/digest before the separately authorized install. Migration repair code is in scope; running an installed migration is not authorized here.
