# SpeakSharp mobile store readiness

**Deliverable:** A side-by-side Apple App Store and Google Play gate matrix.
**Expected outcome:** Each store build can be reviewed end-to-end, with exact build and device evidence for every applicable requirement. No item is considered passed merely because a PR is merged.
**Baseline:** 2026-11-23. Current repo ships a mobile web experience, not verified store binaries. Recheck platform rules and storefront scope before submission.

| Gate | Apple App Store | Google Play | Evidence required |
| --- | --- | --- | --- |
| Build and core utility | Signed iOS build; current upload requirement Xcode 26+ with iOS 26 SDK. App Review §4.2: substantive app experience, not just a repackaged site. [SDK](https://developer.apple.com/news/upcoming-requirements/) · [Review](https://developer.apple.com/app-store/review/guidelines/) | Signed Android App Bundle; Android 16/API 36 for new phone submissions; Play App Signing and 16 KB compatibility for native libraries. Stable core functionality. [Target API](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en) · [App signing](https://developer.android.com/studio/publish/app-signing) · [Page size](https://developer.android.com/guide/practices/page-sizes) | Signed build IDs, private test-track install on physical phones, mic Allow/Deny, cold Private setup, recording, Stop, save, review/reopen/repeat, full/partial Focus, and interruption recovery. Desktop viewport tests are supporting evidence only. |
| Digital subscription | Default to StoreKit In-App Purchase for new purchases in the app; validate any storefront-specific exception before using it. Keep a way to restore eligible purchases. [§3.1](https://developer.apple.com/app-store/review/guidelines/#business) | Default to Play Billing for new in-app subscriptions; external payment only under an applicable approved program or policy. [Payments](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en) | Same full features for new users for 30 days, then pay to continue. Sandbox trial, expiry, purchase, restore/re-sign-in, cancellation, refund/revocation and entitlement reconciliation; no duplicate charge or cross-owner restore. |
| Delete account and data | Users can initiate account deletion in the app. Tell users the timing, retained data and subscription implications clearly. [§5.1.1(v)](https://developer.apple.com/support/offering-account-deletion-in-your-app/) | A discoverable in-app deletion path plus a functional external web resource listed in Play Console. [Deletion](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en) | [#1740](https://github.com/relativityE/speaksharp/pull/1740) merged implementation source; [#1643](https://github.com/relativityE/speaksharp/issues/1643) original customer contract; [#1952](https://github.com/relativityE/speaksharp/pull/1952) safe rollout plan; [#1953](https://github.com/relativityE/speaksharp/pull/1953) negative-control proof only. Both store routes must work to verified completion on authorized disposable accounts; a disabled button does not pass. |
| Privacy and permissions | Mic usage string and consent, privacy policy and App Privacy answers, applicable SDK privacy manifests/required-reason APIs. Disclose and obtain explicit permission before sharing personal data with third-party AI. [Privacy labels](https://developer.apple.com/app-store/app-privacy-details/) · [SDK requirements](https://developer.apple.com/support/third-party-SDK-requirements/) · [AI consent](https://developer.apple.com/news/?id=ey6d8onl) | Mic runtime permission, privacy policy, Data safety and applicable prominent disclosure/consent; determine whether AI coaching is covered by the in-app reporting requirement. [User Data](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en) · [AI policy](https://support.google.com/googleplay/android-developer/answer/14094294?hl=en) | Signed-build network/data inventory matches actual choices and both forms. No transcript/provider traffic when the relevant choice is off; no audio upload in Private. Inventory dependencies, telemetry, support, and data retention separately. |
| Listing and reviewer access | Supported-size screenshots, current age rating, metadata, support/privacy URLs, working demo account or eligible full demo mode. [Review](https://developer.apple.com/app-store/review/guidelines/) | Screenshots, content rating/target-audience declarations, privacy and deletion URLs and App Access instructions. [Prepare for review](https://support.google.com/googleplay/android-developer/answer/9859455?hl=en) · [Closed test](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en) | Store-specific capture list, verified HTTPS links, rating answers checked against build, and reviewer can reach post-trial features without a real charge. | Conditional gates | Check §4.8 if third-party/social login is added, and country-specific declarations/rights. | Check developer account verification, organization/personal classification, target region and policy declarations. | Record applicable/not applicable and why; check account status in the consoles, not in code. |

## Execution order
1. In parallel, scope the signed builds, store billing, deletion implementation, and disclosure cleanup. Verify developer-account setup and start qualifying closed testing when applicable.
2. Make the deletion design compatible with both stores now. Use an authenticated in-app request path and a real external request page, with one owner-bound backend, clear status and prescribed retention. Preserve existing safeguards. Production deletion rollout and activation remain independently gated.
3. Prepare screenshot, rating, support and reviewer materials against the actual flows. Copy must describe “30 days free, then pay to continue,” not a free feature tier versus Pro. Existing internal Pro strings may remain until release-copy cleanup.
4. Rehearse each signed build end to end on its private test track: new trial, after-trial access and sandbox payment, mic/Private recording and save, privacy choices, reversible subscription management and authorized disposable-account deletion. Save exact build/device/date receipts and explicit failures.
5. Submit only after both applicable checklists are reviewed and pass. No public submission or production change is authorized by this document.
